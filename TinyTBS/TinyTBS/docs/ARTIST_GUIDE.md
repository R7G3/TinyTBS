# Руководство для художника

Правила подготовки **PNG** для TinyTBS (MonoGame). Цель: один набор спрайтов на тип юнита/строения, **цвета игроков** задаются в игре, а не отдельными файлами.

## Общий принцип: base + mask

Для каждого юнита или строения, где нужен **цвет команды** (флаг, плащ, щит, крыша и т.д.):

| Файл | Суффикс | Содержимое |
|------|---------|------------|
| База | `_base.png` | Все **некрасящиеся** детали: лицо, кожа, металл, дерево, камень, тени, контуры |
| Маска | `_team.png` или `_mask_<zone>.png` | Только области **перекраски** |

**Пример имён:**

```
Images/units/knight_base.png
Images/units/knight_team.png

Images/buildings/castle_base.png
Images/buildings/castle_roof_mask.png
Images/buildings/castle_flag_mask.png
```

Игра рисует: сначала `_base`, затем маску с цветом игрока.

## Правила для маски (`_team`, `_mask_*`)

1. **Форма** — только альфа-канал (силуэт области). RGB маски — **белый** `#FFFFFF` или светло-серый `#CCCCCC` там, где нужна полная насыщенность цвета игрока.
2. **Не рисовать** на маске детали лица, блики, текстуры — только «заливка команды».
3. **Прозрачность** вне зоны перекраски — альфа **0** (полностью прозрачно).
4. **Размер и pivot** маски **совпадают** с `_base` (одинаковые width × height, один anchor / точка привязки к клетке).
5. **Не использовать** полупрозрачные края на маске, если не нужен специальный эффект — иначе цвет игрока будет «грязным».

## Правила для базы (`_base`)

1. В зонах перекраски на `_base` **не должно быть** яркого цвета команды — там либо нейтральная текстура, либо пусто (просвечивает только маска).
2. Сохранять **единый стиль** освещения для всех юнитов одного набора (TBS, читаемость с высоты).
3. Формат: **PNG-32** (RGBA).

## Несколько зон перекраски

Если крыша и флаг могут быть **разного** цвета (редко) — отдельные маски:

- `castle_roof_mask.png`
- `castle_flag_mask.png`

Если одна зона — один `_team.png` достаточно.

## Тайлы местности (surface)

Тайлы карты (луг, вода, дорога, гора, лес, мост) — **обычные PNG**, без масок. Не перекрашиваются под игрока.

## Состояние «юнит уже походил»

**Отдельные файлы не нужны.** Игра затемняет маску программно (`dimFactor` ≈ 0.55). Художник **не** готовит «тёмную» версию.

## Нейтральные строения

Незахваченное строение использует **нейтральный цвет** из палитры игры (не цвет игрока). Маска та же; меняется только `Color` при отрисовке.

## Моды

Структура папок модов **зеркалирует** bundled Content:

```
Mods/MyMod/Images/units/knight_base.png
Mods/MyMod/Images/units/knight_team.png
```

Если в моде нет файла — игра берёт bundled версию.

## Чего не делать

| Не делать | Почему |
|-----------|--------|
| 11 вариантов юнита под каждого игрока | Цвет в рантайме |
| Цветные маски (красный плащ на маске) | Tint исказит оттенок |
| JPEG | Нет альфа |
| Разный размер base и mask | Смещение при отрисовке |
| Tiled / внешний редактор карт для спрайтов | Свой пайплайн игры |

## Опционально (будущее): шейдер с маркерными цветами

Если позже перейдём на **один** PNG вместо base+mask, перекрашиваемые зоны рисуются **строго** маркерными цветами (например `#FF00FF`, `#00FFFF`). Это **не** текущий стандарт — пока только base + mask.

## Чеклист перед сдачей ассета

- [ ] `*_base.png` и `*_team.png` (или `*_mask_*.png`) одного размера
- [ ] Маска: белое + альфа только в зонах команды
- [ ] На base нет «чужого» цвета команды в зонах маски
- [ ] PNG-32, прозрачный фон где нужно
- [ ] Имена в lowercase, путь `Images/units/` или `Images/buildings/`

## Контакт с кодом

Рендер: два вызова `SpriteBatch.Draw` — base (`Color.White`), mask (`playerColor`). См. [adr/0004-sprite-base-mask-recoloring.md](adr/0004-sprite-base-mask-recoloring.md).
