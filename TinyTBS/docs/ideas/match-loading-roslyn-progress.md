# Загрузка матча: Roslyn + экран прогресса

- **Статус:** idea  
- **Дата:** 2026-09-21  
- **Контекст:** после шага map-scripting первый вход в матч заметно тормозит

## Наблюдение

При старте матча `GameplaySessionFactory` каждый раз:

1. читает `script.cs` карты;
2. валидирует текст;
3. **компилирует** через Roslyn (`CSharpCompilation` + `Emit`);
4. грузит сборку в процесс;
5. вызывает `OnPlayerTurnStart`.

Особенно дорого **первый** запуск в жизни процесса: холодная подгрузка и JIT сборок Roslyn (часто секунды). Повторный матч в том же процессе обычно быстрее, но компиляция всё равно повторяется без кэша.

## Возможные ускорения (позже)

| Идея | Смысл |
|------|--------|
| Кэш по пути + хэш исходника | Не компилировать повторно одну и ту же карту в сессии / на диске |
| Прогрев Roslyn при старте игры | Сдвинуть cold start на меню / splash |
| Precompile bundled-карт | Vanilla без Roslyn в рантайме (удобно и для Android) |
| Фоновая компиляция | Пока игрок в лобби «Новая игра» |

## Загрузочный экран со шкалой прогресса

Рассмотреть **loading screen** при входе в матч (и, при необходимости, при старте приложения):

- шкалы / этапы: level + map → скрипт (Roslyn) → текстуры / атлас → сцена;
- не блокировать UI-тред без обратной связи — прогресс по завершённым шагам (хотя бы дискретным);
- текст этапа («Compiling map script…», «Loading textures…») полезен для отладки и честности к игроку;
- на слабых устройствах / Android без прогресса длинная пауза выглядит как зависание.

Связь с UI-каноном: при полировке flow ([UI_AND_FLOW](../design/UI_AND_FLOW.md)) — отдельный короткий экран или оверлей поверх перехода Menu → Gameplay.

## Когда вернуться

После playable loop / при жалобах на старт матча; либо вместе с match-ui / Android-hosted scripting (Lua/precompile).
