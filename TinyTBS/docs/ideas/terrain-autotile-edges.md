# Автотайлинг местности (берега / стыки по соседям)

- **Статус:** idea (часть решений зафиксирована 2026-09-28; **перед кодом — обязательный gate** с вопросами ниже)
- **Дата:** 2026-09-28
- **Слот roadmap:** `terrain-autotile` после `ui-scale-hidpi`, перед `network-later` — см. [ARCHITECTURE](../ARCHITECTURE.md)
- **Контекст:** карты выглядят «слишком квадратно»; хочется мягких стыков (трава↔вода и др.) без ручной расстановки береговых тайлов на карте.

## Идея

Клетка по-прежнему хранит один `TerrainKind`. При bake/draw рендерер смотрит **4 соседей** (N/E/S/W, без диагоналей) и подставляет вариацию спрайта (+ поворот), чтобы край стыковался с «чужой» местностью.

Логика хода/защиты **не** меняется — только theme/visual.

## Зафиксированные решения (до gate)

| # | Решение |
|---|---------|
| Пары | Цель — стыки **всех** видов местности (не только трава/вода); **как** именно — см. gate Q1 |
| Соседи | Только **4 стороны** (без диагоналей) |
| Кто рисует край (черновик) | На клетке «своего» типа (пример: берег на **траве** к воде); политика при конфликте двух kinds — gate Q2 |
| Fill | Один fill на kind, без random variants |
| Пролив (вода N+S или E+W) | **Отдельный** тайл opposite (не два 1-side) |
| Мост | **Ломает** правило берега — точная семантика: gate Q3 |
| Fallback | Нет полного набора вариаций → простой рендер как сейчас; строгость частичного набора — gate Q4 |
| Приоритет | Между `ui-scale-hidpi` и `network-later` |

## Набор арта (4-neighbor bitmask)

Для бинарной маски «свой / чужой сосед» существует ровно **16** комбинаций. С поворотами уникальных кусков:

| Маска (идея) | Уникальный ассет | Покрывает |
|--------------|------------------|-----------|
| 0 сторон | fill | внутри массива |
| 1 сторона | edge-1 | N/E/S/W |
| 2 смежные (угол) | corner-2 | NE/ES/SW/WN |
| 2 противоположные | opposite | N+S и E+W (поворот 90°) |
| 3 стороны | edge-3 | «U» / почти-остров |
| 4 стороны | island | островок |

**Забытых комбинаций для 4-соседей (свой/чужой) нет.**

Диагонали (внутренний/внешний угол «по пикселю») **не** входят в v1 → берег слегка ступенчатый на углах — осознанный tradeoff (пересмотр — gate Q5).

## Набросок реализации

1. Расширить theme: обнаружение variant set / манифест.
2. `TerrainAutotileResolver`: маска → (texture, rotation).
3. Bake в `MatchScene` + rotation в `TilemapDrawSystem`.
4. Редактор позже — тот же resolver для превью.

Карточный JSON не меняется.

## Когда не делать

Не вклинивать в playtest-приоритет (бот / сейвы / кампании / редактор). После HiDPI.

## Открыто — пояснения (для агента / человека)

### Термины (кратко)

| Термин | Смысл | Пример |
|--------|--------|--------|
| **Автотайлинг** | Выбор картинки клетки по соседям, а не вручную на карте | Трава у воды сама становится «берегом» |
| **4-neighbor** | Смотрим только север/восток/юг/запад | Диагональная вода **не** влияет на маску |
| **Bitmask** | 4 бита «есть чужой сосед?» → число 0…15 → вариант тайла | Чужие N+E → угол |
| **Fill** | Тайл «внутри» массива, без краёв | Поле травы далеко от воды |
| **Edge-1 / corner-2 / opposite / edge-3 / island** | Уникальные куски арта (с поворотами покрывают все 16 масок) | Пролив N+S → **opposite**, не два edge-1 |
| **Бинарный край** | Сосед либо «свой», либо «чужой»; вид края один | Трава→вода и трава→дорога **одной** картинкой края |
| **Край по типу соседа** | Отдельный набор арта на пару kinds | `grass→water` ≠ `grass→road` |
| **Приоритет соседей** | Если чужих несколько типов, в маску идёт только «важнейший» | Вода важнее дороги → у травы рисуем водный берег, дорогу игнорим для маски |
| **Fallback / simple mode** | Нет вариаций → один тайл на kind, как сейчас | Старый theme-мод без папки edges |
| **All-or-nothing** | Либо полный набор кусков на kind → автотайл, либо весь kind в simple | Нет `island.png` → трава всегда fill |

### 1. Семантика «всех пар» (A / B / C)

Нужно стыковать **все** виды местности, но арт и код зависят от того, *что* считать «чужим» и *какой* спрайт края брать.

**Пример клетки:** трава; север — вода, восток — дорога, юг/запад — трава.

| Вариант | Что увидит игрок | Арт | Сложность кода | Оценка |
|---------|------------------|-----|----------------|--------|
| **A. Бинарный** | Один «край» (как берег), маска = N+E → corner | 1 набор на kind | Низкая | Быстрый ship; трава у дороги выглядит как «берег» — может раздражать |
| **B. По типу соседа** | Отдельный берег к воде **и** отдельный стык к дороге | Наборы × (kinds−1) на каждый kind | Высокая (несколько масок / слои) | Максимум контроля; дорого для vanilla и модов |
| **C. Приоритет** | В маску только вода (если вода > дорога); дорожный стык не рисуется | 1 набор «к важному» или мало наборов | Средняя | Компромисс: красивая вода, дорога остаётся «квадратной» к траве |

**Рекомендация агента по умолчанию (не решение):** начать с **A** или **C** для vanilla; B — если после playtest явно нужны разные материалы стыка.

### 2. Кто рисует стык

Две соседние клетки разных kinds обе могут «хотеть» нарисовать край.

**Пример:** трава | вода.

| Политика | Результат | Плюсы | Минусы |
|----------|-----------|-------|--------|
| **Только «верхний» kind** (таблица приоритетов: напр. суша рисует к воде, вода всегда fill) | Берег на траве, вода — сплошная | Меньше наложений, проще арт | Нужна согласованная таблица приоритетов |
| **Оба рисуют** | Край на траве + край на воде | Симметрия | Двойной контур / конфликт пикселей |
| **Односторонние правила** (только white-list пар: grass→water, не water→grass) | Явный список | Предсказуемо | Длинный список пар; легко забыть пару |

Связано с Q1: при **B** почти неизбежны односторонние пары; при **A/C** чаще хватает «один художник на стык».

### 3. Мост ломает берег — семантика

Зафиксировано намерение: мост **не** как обычная вода для берега. Нужна точная модель.

**Пример:** трава | мост | вода (мост между травой и водой по линии).

| Интерпретация | Сосед травы = мост | Сосед воды = мост | Оценка |
|---------------|--------------------|-------------------|--------|
| **M1.** Мост = «свой» для всех (игнор в маске как чужой) | Трава не берег | Вода не «берег к мосту» | Проще всего; мост как нейтральный разделитель |
| **M2.** Мост = свой только для суши; для воды — чужой | Трава не берег | Вода может рисовать край к мосту | Асимметрия; арт воды к мосту |
| **M3.** Мост сам в автотайле позже; пока fill | Как M1 для соседей | — | Хороший v1: не трогать мост-набор |

**Рекомендация агента:** **M1** или **M3** для первого среза.

### 4. Fallback: all-or-nothing vs мягкая деградация

| Вариант | Поведение | Плюсы | Минусы |
|---------|-----------|-------|--------|
| **All-or-nothing на kind** | Нет любого из 6 кусков → весь kind simple | Нет дыр на островках; предсказуемо для моддеров | Нельзя «почти готовый» набор |
| **Мягкая деградация** | Нет island → на маске 15 рисуем fill или edge-3 | Можно шипить арт кусками | Редкие визуальные глитчи; сложнее тестировать |
| **All-or-nothing на весь theme** | Нет полного набора хотя бы у одного kind → весь theme simple | Ещё жёстче | Наказание за один недоделанный kind |

**Рекомендация агента:** all-or-nothing **на kind** (уже в черновике решений).

### 5. Диагонали в v1

| Вариант | Смысл | Оценка |
|---------|--------|--------|
| **Нет (как сейчас в решениях)** | Только 4 стороны; углы карты ступенчатые | Меньше арта; достаточно для soft coast |
| **Заложить API под 8-neighbor later** | В коде маска/resolver расширяемы, арт v1 без диагоналей | Чуть сложнее контракт; не блокирует v1 |
| **Сразу 8-neighbor** | Внутренние/внешние уголки | Сильно больше арта; не для текущего слота |

### 6. Контракт theme: имена файлов vs манифест

| Вариант | Пример | Плюсы | Минусы |
|---------|--------|-------|--------|
| **Convention** | `terrain/grass/fill.png`, `edge_1.png`, … | Проще моддеру «кинуть файлы» | Жёсткие имена; хуже i18n/альтернативы |
| **Манифест в module.json** | Явные пути на роли | Гибко, валидируется | Больше JSON |
| **Hybrid** | Convention по умолчанию + опциональный override в JSON | Удобно vanilla + гибкость модов | Два пути в коде |

**Рекомендация агента:** **Hybrid** или чистый convention для v1.
