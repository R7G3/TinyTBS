# Бот: сложность через оценку и глубину мысли

- **Статус:** idea  
- **Дата:** 2026-09-27  
- **Контекст:** в UI схватке уже есть «локальный / бот» ([UI_AND_FLOW](../design/UI_AND_FLOW.md)); AI в коде нет. Хочется Easy / Normal / Hard **без читов** (лишнее золото, скрытый урон и т.п.) — только качество оценки позиции и глубина поиска. Решение по варианту и слоту в roadmap — позже.

## Ограничения канона

- **Детерминизм** ([GAME_DESIGN](../GAME_DESIGN.md)): исходы боя без рандома. «Ошибки» лёгкого бота лучше делать урезанным поиском / грубой эвристикой, а не случайным промахом.
- Честный бот играет **теми же правилами**, что человек (те же команды / симуляция состояния).
- Практично после (или вместе с) `match-combat-gdd` и `match-economy-capture`: иначе нечего честно оценивать.



## Каркас (любой выбранный вариант)

```text
LegalActions → SearchPolicy(difficulty) → PositionEval → ChooseAction → Apply (как у human)
```

Сложность крутит только поиск и эвристику, не экономику/урон.

## Варианты


| #   | Подход                          | Смысл сложности                                                       | Плюсы                        | Минусы                                                 |
| --- | ------------------------------- | --------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------ |
| 1   | Жадный ход + эвристика          | Easy — короткая эвристика; Hard — богаче веса (угрозы, доход, захват) | Быстро к играбельному боту   | Слаб на комбинациях / жертвах                          |
| 2   | Поиск по глубине (minimax / αβ) | Easy: глубина 0–1; Normal: 1–2; Hard: 2–3 + quiescence                | Прямо «глубина мысли»        | Большое ветвление TBS → pruning / лимит узлов          |
| 3   | MCTS                            | Сила через число playouts                                             | Универсально в других жанрах | Плохо стыкуется с детерминизмом; не основа для TinyTBS |
| 4   | Скриптовые цели поверх 1/2      | Кампания: «беги к деревне»                                            | Гибко для сценариев          | Не замена Hard в схватке                               |
| 5   | Нейросеть / обучение            | Отдельный пайплайн                                                    | Потенциал силы               | Избыточно для v1, пока формулы ещё сходятся с GDD      |




## Рычаги Easy / Normal / Hard (без читов)


| Рычаг                       | Easy                 | Normal              | Hard                     |
| --------------------------- | -------------------- | ------------------- | ------------------------ |
| Глубина / лимит узлов       | 0–1                  | 1–2                 | 2–3+                     |
| Эвристика                   | «урон сейчас»        | + доход, захват, HP | + угрозы, темп, синергия |
| Горизонт найма              | слабый               | нормальный          | план на 2–3 хода         |
| Порядок рассмотрения юнитов | плохой/фиксированный | разумный            | лучшие ходы раньше       |


**Не делать:** hidden gold, +damage, односторонний fog, чтение скриптов карты «с будущего».

## Черновая дорожка (когда примем)

1. `IMatchActor` — human (ввод) / bot (AI) → те же команды, что applicator.
2. `LegalActionGenerator` + симуляция на копии `MatchState`.
3. `PositionEvaluator` (армия, экономика, победа, деревни).
4. `BotSearch` + профиль `BotDifficulty`.
5. Старт с **варианта 1**, API сразу под **вариант 2** без смены контракта.
