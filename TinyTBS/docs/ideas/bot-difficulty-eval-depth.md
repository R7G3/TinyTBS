# Бот: сложность через оценку и глубину мысли

- **Статус:** принят вариант **2** (minimax / αβ); слот roadmap — `bot-search-ab` **сразу после** `match-gdd-loop` (перед сейвами/кампаниями/редактором); `player-colors` / settings **не** блокируют
- **Дата:** 2026-09-27 (выбор варианта / слот: 2026-09-28; пересортировка playtest: 2026-09-28)
- **Контекст:** в UI схватке уже есть «локальный / бот» ([UI_AND_FLOW](../design/UI_AND_FLOW.md)); AI в коде нет. Сложность **без читов** — только качество оценки и глубина поиска.
- **Срез до playtest-перерыва:** **Easy + Normal** (оба нужны: оценка баланса на перерыве займёт время). **Hard** — отдельным follow-up после перерыва / оценки Easy·Normal.

## Ограничения канона

- **Детерминизм** ([GAME_DESIGN](../GAME_DESIGN.md)): исходы боя без рандома. «Ошибки» лёгкого бота — урезанный поиск / грубая эвристика, не случайный промах.
- Честный бот играет **теми же правилами**, что человек (те же команды / симуляция состояния).
- Делать **после** `match-gdd-loop` (economy + combat). DimFactor / `player-colors` желательны для красоты лобби, но **не** обязательны перед ботом.



## Каркас (любой выбранный вариант)

```text
LegalActions → SearchPolicy(difficulty) → PositionEval → ChooseAction → Apply (как у human)
```

Сложность крутит только поиск и эвристику, не экономику/урон.

| Рычаг                       | Easy                 | Normal              | Hard                     |
| --------------------------- | -------------------- | ------------------- | ------------------------ |
| Глубина / лимит узлов       | 0–1                  | 1–2                 | 2–3+                     |

## Черновая дорожка (`bot-search-ab`)

1. `IMatchActor` — human (ввод) / bot (AI) → те же команды, что applicator.
2. `LegalActionGenerator` + симуляция на копии `MatchState`.
3. `PositionEvaluator` (армия, экономика, победа, деревни).
4. `BotSearch` (αβ) + профиль `BotDifficulty` — **Easy + Normal** в первом срезе; **Hard** (+ quiescence по решению gate) позже.
5. Подробные комментарии в коде, как устроен поиск и почему глубина = «сила мысли».
6. Лобби: слот Bot + выбор Easy/Normal (Hard greyed или скрыт до follow-up).

## Открыто — пояснения (для агента / человека)

### 1. Гранулярность хода в дереве

В TBS «один ход» = много мелких действий (сдвинуть юнит A, потом B, нанять, закончить ход). Дерево поиска может строиться по-разному:

| Подход | Суть | Плюсы | Минусы |
|--------|------|-------|--------|
| **Атомарные команды** | Узел = одно действие (`Move`, `Recruit`, `EndTurn`) | Проще симулировать тем же applicator; αβ режет ветки рано | Глубина «2» ≠ два полных хода игрока; дерево огромное без лимита узлов |
| **Весь ход игрока** | Узел = полная последовательность до `EndTurn` | Глубина читается как «ходы вперёд» | Комбинаторный взрыв внутри одного хода; нужен отдельный генератор «планов хода» |

От этого зависит смысл Easy/Normal/Hard (ply vs полный ход) и стоимость CPU.

### 2. Quiescence (только Hard / ещё Normal?)

**Quiescence** — после достижения лимита глубины не останавливаться сразу, а досмотреть «шумные» тактические продолжения (например обмен ударами), чтобы оценка не врала на середине драки.

- Только **Hard** — Normal быстрее и проще; Hard заметно умнее в бою.
- **Normal + Hard** — Normal ближе к Hard по тактике, но дольше думать; Easy по-прежнему «глубина 0–1 без quiescence».

### 3. Unit-test harness без полного UI

Отдельный прогон: задать `MatchState` + сложность → получить выбранное действие / score, без Gum и экрана матча.

- **Да** — ловим регрессии αβ/эвристики при правках combat/economy; удобно отлаживать детерминизм.
- **Нет (сначала)** — меньше работы на v1; риск ломать поиск незаметно; можно добавить после первого играбельного бота.
