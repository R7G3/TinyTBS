# Геймдизайн TinyTBS

> **Канон геймдизайна** для людей и для AI. Источник-черновик: [`TinyTBS_design_source.txt`](../TinyTBS_design_source.txt).  
> При расхождении побеждает этот каталог `docs/` (и `docs/design/`).

**Жанр:** пошаговая стратегия с упором на тактику.

Связанная архитектура: [ARCHITECTURE.md](ARCHITECTURE.md). Форматы: [MAP_FORMAT.md](MAP_FORMAT.md), [LEVEL_FORMAT.md](LEVEL_FORMAT.md), [CAMPAIGN_FORMAT.md](CAMPAIGN_FORMAT.md), [UNIT_FORMAT.md](UNIT_FORMAT.md).

## Ключевой цикл

```text
[ Захват деревень ] → [ Золото ] → [ Найм в замках ]
        ↑                                    ↓
[ Контроль карты ] ← [ Бои / победа ] ← [ Манёвры ]
```

## Столпы

| Столп | Суть |
|-------|------|
| **Детерминизм** | Без рандома: урон и исходы считаются однозначно и воспроизводимо. |
| **Цена ранения** | Урон зависит от текущего HP атакующего; ветераны ценны; лечение и добивания — тактика. |
| **Ландшафт** | Местность сильно влияет на скорость и защиту; замок на горе — твердыня. |
| **Экономика** | Строения дают доход, лечение и броню; иногда важнее удержать деревни, чем убить отряд. |
| **Синергия** | Связки классов сильнее «пачки дорогих» одинаковых юнитов. |

## Map → Level → Campaign

Один каркас данных (не три разных «мира»):

| Сущность | Роль |
|----------|------|
| **Map** | Доска: terrain, строения, слоты/стартовые юниты, скрипт доски; опционально стартовые памятные камни (экземпляры). |
| **Level** | Играбельная партия: map **внутри** пакета *или* **ссылка** на `.map.zip`; игроки/команды; золото; лимит юнитов; win/lose; теги skirmish/campaign; диалоги. |
| **Campaign** | Порядок levels, сюжет/метапрогресс, campaign script — не лобби схватки. |

Свобода авторам: один формат, две упаковки Level (embed vs reference). Подробнее: [LEVEL_FORMAT.md](LEVEL_FORMAT.md), [adr/0006-map-level-campaign.md](adr/0006-map-level-campaign.md).

## Игроки и режимы

**Тип игрока:** ИИ, локальный человек, удалённый человек (сеть — **позже** в roadmap; API закладывать с типом Remote).

**Команды:** союзники не атакуют друг друга. Поражение команды по умолчанию — когда побеждены **все** участники; опция уровня/мода — поражение **любого** = поражение команды.

**Кампания** — наборы levels + опциональная метапрогрессия; может быть частью мода.

**Схватка** — один level/map; создатель задаёт состав игроков/команд и может переопределить стартовое золото и лимит юнитов.

## Моды = content packs

Мод может быть «игрой на движке»: юниты, строения, баланс, карты/уровни, кампании, ассеты, скрипты, условия победы.

Vanilla TinyTBS — тоже content pack в **том же** формате данных, что и сторонние моды.

Нестандартный юнит описывается **конфигом** (статы + способности-verbs + правила `special` к фиксированной формуле), а не отдельным движком. См. [UNITS.md](design/UNITS.md) и [UNIT_FORMAT.md](UNIT_FORMAT.md).

Сейчас в коде в основном override графики/звука; полные content-моды — целевая архитектура.

## Победа и поражение (стандарт)

- **Победа:** победить королей соперников и захватить все их замки (для 3+ игроков — всех соперников; для команд — масштаб на команду).
- **Поражение игрока:** нет короля и нет замков (нельзя нанять и нельзя захватить замок без короля).
- Уровень может **заменить** условия кастомными.

При выбывании игрока в матче на 3+: его юниты исчезают **без** памятных камней, строения становятся нейтральными. В дуэли на 2 игроков матч сразу заканчивается.

## Расхождение с текущим демо-кодом

Демо `MatchState`: сетка 8×8, ход на 1 клетку, без экономики/боя по формуле. Это прототип склейки слоёв, **не** полный GDD. Сходимость кода с этим документом — по roadmap после Map/Level.
